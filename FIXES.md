# Исправленные дефекты в Source SDK 2013

Сводка по всем багам из аудита, которые были исправлены. Правки касаются
численной устойчивости и явных логических ошибок в `mathlib`, `tier1` и
публичных заголовках. Геймплейная логика HL2/TF и поведение, которое по
факту является соглашением движка (кодировка углов, порядок аргументов,
формат сетевых кватернионов), **сознательно не менялись** — см. последний
раздел.

Всего изменено 17 файлов. Проверка: `g++ -fsyntax-only` по каждому файлу
проходит, рантайм-регресс (56 проверок, линкуется с реальными `mathlib` и
`tier1`) — **56 passed, 0 failed**.

## 1. `src/public/mathlib/mathlib.h`

| Что было | Что стало |
|---|---|
| `anglemod()` приводил `a*65536/360` к `int`, т.е. усекал к нулю. Из-за этого `anglemod(1) == 0.99976`, а `anglemod(-1) == 359.0` (разные шаги квантования для знаков), а большие углы переполняли `int`. | Сначала `fmod(a, 360)`, затем округление к ближайшему `floor(x+0.5)` и маска `& 65535`. Отображение стало симметричным, переполнения нет. |
| `VectorLength(const float *)` возвращал `FastSqrt(sum + FLT_EPSILON)` — длина систематически завышалась: вектор длиной `1e-4` измерялся как `3.6e-4`, и результат расходился с `Vector::Length()`. | Реальная сумма квадратов, явная ветка нулевой длины → `0.0f`. |
| `FLerp()` при `i1 == i2` делил на ноль → NaN/Inf. | Возвращает `f1` (как `RemapVal` при `A == B`). |
| `AngleDistance()` считал `abs(a-b)`, игнорируя переход через 360: `AngleDistance(10, 350)` давал 340 вместо 20. | Через `AngleDiff()`, т.е. кратчайшая дуга; `AngleDistance(0, 720) == 0`. |
| `AnglesAreEqual()` использовал строгие `<` для сравнения с допуском, т.е. ровно на границе допуска углы считались разными. | Инклюзивное `<=`. |

## Что сознательно не менялось

Это не недосмотр: перечисленные места выглядят подозрительно, но их
поведение — соглашение движка или воспроизводится точь-в-точь.

- **`MatrixAngles` и gimbal-ветка `VectorAngles`.** Матрица восстанавливается
  точно (расхождение 0.02°). Формат углов Эйлера — часть сетевого протокола
  и демо-файлов; «исправление» сломало бы совместимость.
- **`QuaternionAxisAngle`, флип оси.** Исходная согласованность `axis·angle`
  верна. Попытка «починить» её через `angle -= 360` вместе с флипом оси дала
  `(0,0,-170)` вместо `(0,0,170)` — откатано, оставлен только
  `if (angle > 180) angle -= 360`.
- **`QuaternionScale`.** `+FLT_EPSILON` в знаменателе `sinsom / (sinom + ε)`
  нужен, чтобы масштабирование оставалось гладким у нуля; при `t = 0` даёт
  identity, при `t = 1` — исходный кватернион. Корректно, не трогал.
- **Алиасинг в `MatrixMultiply`.** `vmatrix.cpp` уже копирует входы в
  `tmp1/tmp2`, если `src` совпадает с `dst`.
- **`CalcSqrDistanceToAABB` / `CalcClosestPointOnAABB`.** Проверены — работают.
- **`Normal32` на реальных нормалях.** Устойчив.
- **Порядок аргументов `MatrixBuildRotationAboutAxis`.** Это API-контракт
  (`axis, angle`), менять нельзя.
- **Геймплейная логика HL2/TF** (`game/mod_hl2mp`, `game/mod_tf`) — вне
  объёма задачи.

## Как воспроизвести проверку

```sh
INC="-Isrc/public -Isrc -Isrc/public/tier0 -Isrc/public/tier1 \
     -Isrc/public/mathlib -Isrc/public/vstdlib -Isrc/mathlib -Isrc/tier1"
DEFS="-DCOMPILER_GCC -DGNUC -D_LINUX -DPOSIX -DLINUX -DPLATFORM_POSIX"

# синтаксис
g++ -fsyntax-only -O1 $INC $DEFS src/mathlib/mathlib_base.cpp

# объектники
g++ -c -O1 $INC $DEFS src/mathlib/mathlib_base.cpp -o mathlib_base.o
# ... то же для vmatrix.cpp, spherical.cpp, sse.cpp, halton.cpp, ../tier1/bitbuf.cpp
```

`-DCOMPILER_GCC` обязателен: без него `platform.h:591` выдаёт `#error`.
Рантайм-регресс линкуется с этими объектниками плюс заглушки
`g_SIMD_ComponentMask`, `HushAsserts`, `BuildGammaTable`,
`GetCPUInformation`.
